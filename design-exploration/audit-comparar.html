High A-09 matchPctPara hace Array.find O(n) dos veces por render — usar Map como CandidatosScreen

matchPctPara() hace un Array.find lineal sobre todos los resultados de matches en cada render del componente, llamado dos veces (slot A y slot B). CandidatosScreen ya resolvio este patron correctamente con un Map<id, pct> en useMemo. El mismo patron debe aplicarse aqui para consistencia y rendimiento.

Actual -- Array.find x2 por render
1
matchPctA = matchPctPara(candidatoA?.id, matchesQ.data)
O(n) Array.find sobre todos los matches
2
matchPctB = matchPctPara(candidatoB?.id, matchesQ.data)
O(n) segundo Array.find en el mismo render
!
Se repite en cada re-render aunque matchesQ.data no haya cambiado. Con 1000+ candidatos, notable.
→
Propuesto -- Map en useMemo + lookup O(1)
1
matchByCandidatoId = useMemo(..., [matchesQ.data])
O(n) una sola vez, solo cuando cambian los datos
2
matchPctA = matchByCandidatoId.get(candidatoA.id)
O(1) lookup instantaneo
3
matchPctB = matchByCandidatoId.get(candidatoB.id)
O(1) segundo lookup instantaneo
// CompararScreen.tsx -- antes
const matchPctA = matchPctPara(candidatoA?.id, matchesQ.data);
const matchPctB = matchPctPara(candidatoB?.id, matchesQ.data);

// CompararScreen.tsx -- despues: Map + useMemo (patron de CandidatosScreen)
const matchByCandidatoId = useMemo(() => {
  const map = new Map<number, number>();
  for (const m of matchesQ.data ?? []) {

    if (id != null && Number.isFinite(n)) map.set(id, Math.round(n));
  }
  return map;
}, [matchesQ.data]);

Med M-26 handleSelectPicker sin useCallback -- prop inestable hacia CandidatoPickerModal

handleSelectPicker se pasa como onSelect a CandidatoPickerModal. Sin useCallback, el modal recibe una referencia nueva en cada render, incluyendo cada vez que el usuario tipea en el buscador del modal.

function handleSelectPicker(cand: Candidato) {
  if (pickerOpen === "A") setCandidatoA(cand);
  else if (pickerOpen === "B") setCandidatoB(cand);
  setPickerOpen(null);
}
const handleSelectPicker = useCallback((cand: Candidato) => {
  if (pickerOpen === "A") setCandidatoA(cand);
  else if (pickerOpen === "B") setCandidatoB(cand);
  setPickerOpen(null);
}, [pickerOpen]);
Med M-27 colorNivel usa ?? "#B45309" -- fallback hardcodeado imposible de alcanzar

Low L-10 void badgeVariantNivel -- antipatron para suprimir TypeScript

void expr como tecnica de supresion de "declared but never used" viola el principio YAGNI: la funcion no tiene consumidores actuales. Si se espera un segundo consumidor pronto, se exporta. Si no, se elimina.

// CompararScreen.tsx -- al final del archivo // Se conserva la funcion aunque no se use directamente en el JSX:
// mapea nivel -> variante de Badge y sirve como single source of truth
// por si aparece otro consumidor sin duplicar el switch.
void badgeVariantNivel;
YAGNI: "por si aparece otro consumidor" no justifica mantener codigo muerto. Si el consumidor llega, se agrega entonces. Exportar la funcion es la alternativa correcta si hay razon de creerlo.
void badgeVariantNivel;
// Opcion A: exportar si se espera segundo consumidor
export { badgeVariantNivel };
// Opcion B (YAGNI): eliminar funcion y su comentario
