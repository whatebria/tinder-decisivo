PerfilScreen — Editar Perfil

La pantalla de perfil tiene un bug critico de seguridad: "Cerrar sesion" llama a logout() directo sin invalidar el token en el backend (logoutApi()), dejando la cookie httpOnly activa en web. Ademas, las acciones destructivas (cerrar sesion + eliminar cuenta) estan mezcladas con acciones normales sin zona de peligro visual. El ThemeToggle esta duplicado respecto a ConfiguracionScreen (REFACTOR-005).

Fase 2 · Auditoria UX / UI Profunda
UX
Pantalla con identidad difusa: el titulo es "Mi perfil" pero la pantalla hace: ver datos (read-only), editar ubicacion, cambiar contrasena, cambiar tema, cerrar sesion, y eliminar cuenta. Son 4 responsabilidades distintas. El usuario no sabe si esta en "ver mi perfil" o "gestionar mi cuenta".
Acciones destructivas sin zona visual: "Cerrar sesion" y "Eliminar mi cuenta" estan en la seccion "Cuenta" junto con "Cambiar mi contrasena". No hay separacion visual que le avise al usuario que las dos ultimas son acciones de alto riesgo.
Estado de error sin recuperacion: si perfilQ falla, se muestra "No pudimos cargar tu perfil." sin boton de retry. El usuario queda atascado con un mensaje sin accion posible. Los toasts de exito/error solo funcionan cuando hay datos cargados.
UbicacionPicker sin estado de exito visible: cuando el usuario guarda su ubicacion, el toast de exito aparece pero el picker no muestra ningun feedback inline (checkmark, animacion de confirmacion). El cambio solo se ve si el usuario memoriza el valor anterior.
UI / Design System
Dividers como separadores de seccion: la pantalla usa 3 Dividers horizontales para separar secciones. Pero Divider es un separador de linea fina -- para secciones con contenido heterogeneo (informacion vs acciones vs apariencia), el patron del DS es usar SectionTitle con espaciado, no Divider. Los Dividers hacen la pantalla visualmente plana.
infoCard sin tipo de borde semantico: la tarjeta de informacion (username, email, fecha) tiene el mismo estilo visual que cualquier card del sistema. No hay distincion visual entre datos "leibles" (info card) y datos "editables" (UbicacionPicker). El usuario podria intentar tocar el username esperando poder editarlo.
statsRow sin minWidth responsive: los StatBadge usan minWidth=110 con flexGrow y flexBasis=110. En pantallas muy angostas (<360px) los 3 badges podrian no caber en una fila y el flexWrap los rompe a dos lineas de forma asimetrica (2+1).
Fase 3 · Benchmarking
Apple Settings
Secciones agrupadas con etiquetas claras
Cada grupo de settings tiene un titulo de seccion y un fondo levemente distinto. Las acciones destructivas (eliminar cuenta, reset) estan al final con color rojo.
Adaptacion: usar fondos de seccion distintos o Dividers con mas espaciado para separar informacion / edicion / acciones destructivas.
Duolingo
Zona de peligro visualmente separada
Eliminar cuenta esta en una seccion separada al final, con fondo de advertencia y confirmacion multiple. El usuario entiende el riesgo sin leer.
Adaptacion: DangerZone con c.dangerBg y borde c.danger para agrupar "Cerrar sesion" y "Eliminar cuenta". Mismo patron propuesto para ConfiguracionScreen (UX-033).
Airbnb
Retry en estados de error
Cuando algo falla al cargar, siempre hay un boton "Intentar de nuevo" con el icono de recarga. El usuario tiene agencia para recuperarse.
Adaptacion: en el estado de error de perfilQ, agregar un Button "Intentar de nuevo" que llama a perfilQ.refetch().
Twitter / X
Campos read-only vs editables diferenciados
Los campos que no se pueden editar tienen un fondo distinto o un icono de candado. El usuario sabe de un vistazo que puede y que no puede cambiar.
Adaptacion: agregar una nota discreta debajo del infoCard "Para cambiar tu nombre de usuario, contacta soporte" -- o un icono de candado sutil en los campos no editables.
Notion
Feedback inline en pickers
Cuando se guarda una preferencia, el campo muestra brevemente un checkmark verde antes de volver al estado normal. El usuario recibe confirmacion sin depender del toast.
Adaptacion: en UbicacionPicker, mostrar un estado "guardado" breve (1.5s) con un checkmark despues de que actualizarComuna.mutateAsync resuelve.
Headspace
Pantalla de perfil enfocada
La pantalla de perfil solo muestra datos del usuario y una lista de preferencias. Las acciones destructivas estan en una pantalla separada de "Seguridad" o "Cuenta".
Dado el contexto del proyecto (app movil), esta separacion puede ser excesiva. La DangerZone visual es suficiente sin crear una nueva pantalla.
Fase 4 · Problemas Detectados
Critico
P-C01 · "Cerrar sesion" llama logout() sin logoutApi() — cookie httpOnly web no se invalida
El NavRow "Cerrar sesion" tiene onPress={logout} directo. La funcion logout() del AuthStore solo limpia el estado local (token en SecureStore, userId). NO llama a logoutApi() que es la que invalida el token en el backend y limpia la cookie httpOnly en web. ConfiguracionScreen si tiene este patron correcto en su handleLogout(). El resultado: en plataforma web, el usuario queda "deslogueado" en el frontend pero la sesion del backend sigue activa hasta que expira el token.
PerfilScreen.tsx L214: <NavRow label="Cerrar sesion" onPress={logout} /> (sin logoutApi)
Alto
P-A01 · "Cerrar sesion" y "Eliminar cuenta" en la misma seccion que "Cambiar contrasena" sin zona de peligro
Las tres acciones de la seccion "Cuenta" tienen diferente riesgo: cambiar contrasena es una accion normal, cerrar sesion es una accion de salida, y eliminar cuenta es irreversible. Estan todas en el mismo bloque visual con el mismo estilo. El usuario no puede distinguir el riesgo entre ellas sin leer.
PerfilScreen.tsx L208-222: NavRow x3 en la misma View sin separacion de riesgo
P-A02 · Estado de error sin retry — el usuario queda atascado
Si perfilQ.isLoading=false y perfil=null (error de red), la pantalla muestra "No pudimos cargar tu perfil." sin ningun boton de accion. El usuario no puede reintentar la carga sin salir y volver a entrar a la pantalla. El UbicacionPicker, ThemeToggle y acciones de cuenta siguen siendo accesibles, pero el usuario no sabe sus datos actuales.
PerfilScreen.tsx L160-162: : (<Text...>No pudimos cargar tu perfil.</Text>) -- sin retry
P-A03 · ThemeToggle duplicado (REFACTOR-005)
ThemeToggle aparece en ConfiguracionScreen (seccion "Apariencia") y en PerfilScreen (seccion "Apariencia"). El usuario puede cambiar el tema desde dos pantallas distintas. Viola el principio de single point of control: una preferencia del sistema deberia tener un solo lugar de configuracion. Documentado en REFACTOR-005 -- se resuelve al consolidar la pantalla.
PerfilScreen.tsx L202: <ThemeToggle /> | ConfiguracionScreen.tsx L189: <ThemeToggle />
Medio
P-M01 · CambiarPasswordModal sin feedback de que falta para habilitar el submit
El boton "Cambiar contrasena" esta disabled hasta que canSubmit=true (current no vacio + next.length >= MIN + passwords match). Pero si el usuario escribe una contrasena corta, no ve ningun error bajo el campo "Nueva contrasena" -- el error solo aparece en el campo confirm cuando no coincide. El usuario no entiende por que el boton sigue deshabilitado.
CambiarPasswordModal.tsx L35-36: canSubmit logic -- sin error feedback para password length
P-M02 · InfoCard no indica que los campos son read-only
La tarjeta con username, email y fecha de registro tiene el mismo estilo visual que cualquier card editable del sistema. Un usuario podria intentar tocar el username o el email esperando poder editarlos. No hay icono de candado, ni texto de ayuda, ni diferenciacion visual de "este dato no se puede cambiar desde aqui".
P-M03 · Pantalla con identidad difusa -- 4 responsabilidades mezcladas
El titulo es "Mi perfil" pero la pantalla cubre: (1) ver datos de cuenta, (2) editar ubicacion electoral, (3) cambiar apariencia, (4) gestionar acciones de cuenta (password, logout, eliminar). Ninguna de estas es el objetivo principal de la otra. La pantalla no tiene una tarea primaria clara.
Bajo
P-L01 · UbicacionPicker: "Cargando..." hardcodeado en Field
El sub-componente Field muestra el texto "Cargando..." cuando loading=true, en lugar de un indicador visual. Inconsistente con el patron de la app.
UbicacionPicker.tsx L161: loading ? "Cargando..." : value
P-L02 · UbicacionPicker: chevron como Unicode literal en lugar de Icon
El chevron del Field usa `"\u25BE"` (caracter Unicode). El componente Icon ya existe en el sistema y garantiza renderizado consistente entre plataformas. Los caracteres Unicode pueden variar en tamano y alineacion.
UbicacionPicker.tsx L172: <Text...>{"\u25BE"}</Text>
P-L03 · InfoRow: valueStyle tipado como object en lugar de TextStyle
El prop valueStyle de InfoRow esta tipado como `object`, perdiendo toda la inferencia de TypeScript para estilos de texto. Deberia ser `StyleProp<TextStyle>`.
PerfilScreen.tsx L242: valueStyle?: object;
P-L04 · Handlers async sin useCallback
handleUbicacion, handleCambiarPass y handleEliminar se recrean en cada render del componente. Los tres se pasan como props a componentes hijos (UbicacionPicker, CambiarPasswordModal, EliminarCuentaModal).
Fase 5 · Propuesta de Rediseno
Bloque 1 — Fix critico: logout correcto
Problema: logout() sin logoutApi() -- cookie web activa
Cambio: Reemplazar onPress={logout} por un handler que llame logoutApi() primero, igual que ConfiguracionScreen.
Beneficio: consistencia de comportamiento de cierre de sesion entre pantallas.
Patron UX: Security principle -- logout completo
Bloque 2 — DangerZone para acciones destructivas
Problema: logout y eliminar sin separacion visual
Cambio: Zona final con fondo danger-bg, borde danger, titulo "Zona de peligro", con "Cerrar sesion" y "Eliminar mi cuenta" dentro.
Beneficio: El usuario entiende el riesgo sin leer.
Patron UX: Danger zone (DS-11 P8, Duolingo, GitHub)
Bloque 3 — Retry en estado de error
Problema: error sin recuperacion posible
Cambio: Agregar Button "Intentar de nuevo" que llama perfilQ.refetch() en el estado de error.
Beneficio: El usuario tiene agencia para recuperarse de errores transitorios de red.
Patron UX: Error recovery (Nielsen #9)
Bloque 4 — InfoCard con indicacion read-only
Problema: datos read-only visualmente iguales a editables
Cambio: Agregar una nota discreta debajo del infoCard: "El nombre de usuario y email no se pueden cambiar desde la app."
Beneficio: Elimina la confusion sobre que es editable.
Patron UX: Affordance y visibilidad del sistema (Nielsen #1)
Bloque 5 — Feedback length en CambiarPasswordModal
Problema: boton disabled sin feedback de causa
Cambio: Mostrar error en el campo "Nueva contrasena" cuando next.length > 0 && next.length < PASSWORD_MIN_LENGTH.
Beneficio: El usuario sabe exactamente que falta para poder enviar.
Patron UX: Inline validation (Typeform, formularios modernos)
Bloque 6 — Eliminar ThemeToggle
Problema: ThemeToggle duplicado en Config + Perfil
Cambio: Eliminar el bloque "Apariencia" + ThemeToggle de PerfilScreen. Solo queda en ConfiguracionScreen.
Beneficio: Un solo punto de control para preferencias de tema.
Patron: DRY, single point of control (REFACTOR-005)
