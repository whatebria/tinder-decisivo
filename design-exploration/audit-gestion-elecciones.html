Casos sin manejar
Problema 1: fecha invalida
Si dateIso es un string malformado, new Date(malformed).getTime() retorna NaN. Math.ceil(NaN / ...) = NaN. Math.max(0, NaN) = NaN. El resultado es "NaN dias" en la UI
No hay validacion de que dateIso sea una fecha ISO valida antes de calcular
Problema 2: eleccion pasada
Para fechas en el pasado, Math.max(0, negativo) = 0, mostrando "0 dias". El usuario no sabe si la eleccion esta proxima o si ya paso. Deberia mostrar "Finalizada" o similar
Fase 2 · Auditoria UX / UI Profunda
UX
Tab "Home" activo en pantalla de configuracion: el usuario entra a Gestion de Elecciones desde la tab de Configuracion. Al entrar, la barra de tabs cambia y resalta "Home". El usuario pierde el contexto de navegacion -- no sabe desde donde vino ni a que tab pertenece esta pantalla.
Sin feedback al guardar la preferencia: el Toggle cambia visualmente de inmediato (optimistic UI), pero no hay ningun mensaje que confirme que el cambio fue persistido en secureStorage. Si la escritura falla silenciosamente, el usuario no lo sabria. Un toast breve ("Eleccion activada" / "Eleccion desactivada") daría confianza.
Sin confirmacion al desactivar: desactivar una eleccion la quita del Home y de los Resultados. Es una accion con consecuencias visibles. No hay confirmacion ni undo. El toggle se puede revertir tocandolo de nuevo, pero el usuario no lo sabe a primera vista.
El hero text "Catalogo" no describe la accion: el titulo del hero es "Catalogo" y el del TopBar es "Tus elecciones". La jerarquia es confusa -- hay dos titulos distintos para la misma pantalla. El titulo del TopBar ya dice "Tus elecciones"; el hero "Catalogo" no agrega contexto util.
UI / Design System
Toggle activo usa c.primary (azul): DS-11 P8 especifica brand-secondary para toggles activos. El azul primario en la app comunica CTAs de accion (botones, links), no estados de preferencia activa. El verde secundario es el token semantico correcto para "activado/on".
infoBox sin accessibilityRole: el bloque explicativo de "Como funciona" con icono info no tiene accessibilityRole="note" ni accessibilityLabel explicativo. Screen readers lo leeran como texto plano sin contexto de que es una nota aclaratoria.
Elecciones con fecha pasada: si una eleccion ya ocurrio, la card la muestra igual que una activa pero con "0 dias". Sin distincion visual (gris, tachado, badge "Finalizada"), el usuario no sabe que ya no es relevante.
Fase 3 · Benchmarking

Notificaciones con toggle + toast
Cada canal tiene un toggle de notificaciones. Al activar o desactivar, un toast breve confirma el cambio. El usuario tiene certeza de que fue guardado.
Adaptacion: toast.success("Eleccion activada") / toast.info("Eleccion desactivada") despues de cada toggle exitoso.
Spotify
Toggles con color semantico
Toggles activos usan el verde de Spotify (brand-secondary), no el azul de links/CTAs. El usuario aprende rapidamente que verde = activado.
Adaptacion: Toggle activo con c.secondary (#3A9E7A) -- ya especificado en DS-11 P8.
iOS Settings
Estado "Finalizado" para items inactivos
Los items que ya no son relevantes (funciones deprecadas, suscripciones expiradas) aparecen en gris con una etiqueta de estado explicita.
Adaptacion: elecciones con fecha pasada mostrar con opacity reducida + badge "Finalizada" en lugar de "N dias".
Duolingo
Seleccion de cursos/idiomas
La pantalla de seleccion de idiomas tiene un patron muy similar a GestionElecciones. Items con toggle, secciones "Activos" y "Disponibles". Limpio y enfocado.
El patron actual de GestionElecciones es similar al de Duolingo -- la arquitectura es correcta. Solo faltan el color correcto del toggle y el feedback de persistencia.
Headspace

Fase 4 · Problemas Detectados
Critico
P-C01 · AppShell active="home" en pantalla accedida desde Configuracion
GestionEleccionesScreen usa AppShell con active="home", lo que resalta el tab "Home" en la barra de navegacion inferior mientras el usuario esta en una sub-pantalla de configuracion. El usuario pierde el contexto de navegacion. PerfilScreen usa correctamente active={null} para sub-pantallas de settings.
GestionEleccionesScreen.tsx L131: <AppShell active="home" navigation={navigation}> (tambien en L150 loading state)
Alto
P-A01 · Toggle usa c.primary en lugar de c.secondary (DS-11 P8)
El componente Toggle.tsx usa c.primary (azul) como color del track activo. DS-11 P8 especifica que toggles activos usan --color-brand-secondary (verde). A diferencia de TASK-031 (ThemeToggle), este es el componente base Toggle que afecta a todas las instancias en la app, incluyendo GestionEleccionesScreen. La correccion debe hacerse en Toggle.tsx directamente.
Toggle.tsx L26: backgroundColor: value ? c.primary : c.border
P-A02 · Sin feedback (toast) al persistir preferencia de eleccion
El toggle llama store.toggle() que es async (escribe en secureStorage). Visualmente el switch cambia de inmediato (optimistic UI), pero no hay confirmacion de que el cambio fue persistido. Si secureStorage falla silenciosamente, el estado visual y el estado real quedan desincronizados sin que el usuario lo sepa.
GestionEleccionesScreen.tsx L177: onPress={() => tipo.id && toggle(tipo.id, allIds)} -- sin await ni feedback
Medio
P-M01 · daysUntil retorna "NaN dias" para fechas malformadas
Si tipo.fecha_eleccion es un string invalido, new Date() retorna Invalid Date, Math.ceil(NaN) = NaN, Math.max(0, NaN) = NaN. La UI muestra "NaN dias". No hay validacion de formato ISO ni fallback para fechas invalidas.
GestionEleccionesScreen.tsx L24-30: funcion daysUntil sin validacion de formato
P-M02 · daysUntil retorna "0 dias" para elecciones ya pasadas — sin distincion visual
Para fechas en el pasado Math.max(0, negativo) = 0, mostrando "0 dias". No hay distincion visual entre una eleccion que ocurre hoy y una que ocurrio hace seis meses. Un badge "Finalizada" o texto "Finalizada" permitiria al usuario entender por que la eleccion ya no es relevante.
P-M03 · Hero "Catalogo" y TopBar "Tus elecciones" — dos titulos para la misma pantalla
La pantalla tiene dos titulos: "Tus elecciones" en el ScreenTopBar y "Catalogo" como titulo del hero. El subtitulo explicativo es valioso, pero el titulo "Catalogo" duplica la informacion del TopBar con un nombre distinto, creando una jerarquia confusa.
Bajo
P-L01 · infoBox sin accessibilityRole="note"
El bloque "Como funciona" con el icono info no tiene accessibilityRole en el View contenedor. Screen readers lo leeran como contenido generico sin contexto de que es una nota aclaratoria.
P-L02 · tipo.id && toggle() -- id=0 seria falsy
La guard `tipo.id && toggle(tipo.id, allIds)` previene llamar toggle con id=0 porque 0 es falsy en JS. En la practica los IDs del backend son auto-increment desde 1, por lo que no es un bug activo, pero es una guard incorrecta semanticamente. Deberia ser `tipo.id != null`.
GestionEleccionesScreen.tsx L177/192: tipo.id && toggle(tipo.id, allIds)
P-L03 · styles en useMemo([c]) — patron ineficiente recurrente
Mismo patron documentado en ConfiguracionScreen y otras pantallas. El StyleSheet se regenera en cada cambio de tema.
Fase 5 · Propuesta de Rediseno
Bloque 1 — Fix critico: AppShell active={null}
Problema: tab Home resaltado en pantalla de config
Cambio: Reemplazar active="home" por active={null} en ambos lugares (loading y render principal).
Beneficio: ninguna tab queda resaltada, consistente con PerfilScreen.
Patron: Sub-screen navigation pattern (Apple HIG)
Bloque 2 — Toggle color secundario
Problema: Toggle activo usa c.primary (azul)
Cambio: Toggle.tsx: reemplazar c.primary por c.secondary en el backgroundColor del track activo.
Beneficio: cumple DS-11 P8, semantica "verde = activado" mas natural.
Patron UX: Consistent semantic color (iOS, Android, Spotify)
Bloque 3 — Toast de confirmacion
Problema: sin feedback de persistencia
Cambio: Convertir el toggle.onPress en un handler async que llama toggle() y emite un toast: "Eleccion activada" / "Eleccion desactivada".
Beneficio: el usuario sabe que el cambio fue guardado.
Patron UX: Feedback de sistema (Nielsen #1)
Bloque 4 — daysUntil robusto + estado "Finalizada"
Problema: NaN dias + 0 dias sin distincion
Cambio: Agregar validacion de NaN y retornar "Finalizada" para fechas pasadas en lugar de "0 dias".
Beneficio: el usuario entiende el estado de cada eleccion.
Patron UX: Visibilidad del sistema (Nielsen #1)
