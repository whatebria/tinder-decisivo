Flujo del usuario
Punto de entrada: Tab "Config" en el AppShell
Acciones principales:
1. Editar perfil (→ PerfilScreen)
2. Ver guardados / respuestas (→ sub-screens)

- "Editar perfil" lleva a otro screen con ThemeToggle duplicado
- La opcion "Cerrar sesion" esta al fondo sin zona visual de peligro

Tarea principal: personalizar la experiencia y gestionar la cuenta
KPI impactado: retencion y confianza — un settings bien disenado reduce churning
Conversion: en modo invitado, convertir a usuario registrado

Tension actual: la logica de perfil esta dividida entre ConfiguracionScreen y PerfilScreen, obligando al usuario a navegar a una segunda pantalla para tareas que deberian estar aqui

Fase 2 · Auditoria UX / UI profunda
UX
Arquitectura de informacion rota: "Editar perfil" lleva a PerfilScreen que tiene ThemeToggle, cambiar contrasena, cerrar sesion, y estadisticas de actividad. Son todos settings que deberan estar en ConfiguracionScreen. El usuario tiene que navegar a una sub-pantalla para encontrar settings que espera en el hub principal.
Identidad no reconocible: el accountCard muestra "juan.garcia" derivado del email. El usuario no se reconoce en ese nombre. La API ya tiene el username real disponible en perfilQ.data?.username.
Sin estadisticas de actividad: el usuario no sabe cuanto ha contribuido a la app. Respuestas, favoritos y descartados existen en la API (perfil.contadores) y estan en PerfilScreen pero no en el hub principal de configuracion.
Carga cognitiva del modo invitado: hay dos CTAs para salir del modo invitado ("Crear una cuenta" y "Salir del modo invitado") que hacen exactamente lo mismo (exitGuestMode()). Duplicacion sin diferenciacion.
UI / Visual
Sin zona de peligro visual: DS-11 P8 especifica --color-danger-bg para enmarcar la zona de acciones destructivas. El logout y eliminar cuenta no tienen separacion visual del resto de settings.
Todas las secciones tienen el mismo peso visual: "Cuenta", "Mis datos", "Elecciones", "Apariencia" y "Debug" se ven identicas. No hay jerarquia visual entre secciones primarias y secundarias.
Sin iconos en NavRows: Spotify, Apple Settings, Linear y cualquier settings screen moderno usa iconos para scanability. Las NavRows actuales son solo texto — el usuario tiene que leer cada item para encontrar lo que busca.
Mobile first: el accountCard centra todo pero el tap target del "Editar perfil" button es correcto (full-width). El ThemeToggle Tabs tiene tap targets de ~36px — bajo el minimo WCAG 2.5.5 de 44px.

Fase 4 · Problemas Detectados
Critico
P-C01 · Identidad derivada del email, no del usuario real
El accountCard muestra email.split("@")[0] como nombre. Un usuario con email "juan.garcia.2001@gmail.com" ve "juan.garcia.2001" como su identidad en la app. perfilQ.data?.username ya esta disponible y es el dato correcto.
ConfiguracionScreen.tsx ~L105: const shortName = email ? email.split("@")[0] : "Mi cuenta";
P-C02 · Arquitectura de informacion fragmentada: perfil y settings en dos pantallas
PerfilScreen tiene ThemeToggle, cambiar contrasena, cerrar sesion, estadisticas y ubicacion. ConfiguracionScreen tambien tiene ThemeToggle y cerrar sesion. El usuario tiene dos lugares donde buscar los mismos controles, y ninguno es el correcto por si solo.
Duplicacion: ThemeToggle en ConfiguracionScreen L189 y PerfilScreen L203. Logout en ConfiguracionScreen L253 y PerfilScreen L214.
Alto
P-A01 · Sin zona de peligro visual para acciones destructivas
DS-11 P8 especifica --color-danger-bg para enmarcar la zona de acciones de alto riesgo. El logout usa variant="secondary" (outline azul) — visualmente identico al boton "Editar perfil". No hay separacion semantica entre acciones normales y peligrosas.
ConfiguracionScreen.tsx L253: <Button variant="secondary" onPress={handleLogout}>Cerrar sesion</Button>
P-A02 · handleLogout y handleReactivarTours sin useCallback
Ambas funciones se recrean en cada render y se pasan como props a componentes hijos. Con el ScrollView y multiples NavRows como receptores, esto causa re-renders innecesarios.
ConfiguracionScreen.tsx: async function handleLogout() y async function handleReactivarTours() definidas directamente en el render scope.
P-A03 · ThemeToggle activo usa primary en lugar de secondary
DS-11 P8: "Toggle activo → --color-brand-secondary". El Tabs atom subyacente aplica el color activo usando primary. Violar este token hace que el toggle de tema se vea como un boton de accion principal.
ThemeToggle.tsx usa Tabs que internamente aplica el color seleccionado con c.primary.
Medio
P-M01 · Sin estadisticas de actividad del usuario en el hub
Respuestas, favoritos y descartados estan disponibles via perfilQ.data?.contadores pero solo aparecen en PerfilScreen. El hub principal deberia mostrar este resumen de actividad para dar contexto al usuario.
P-M02 · Modo invitado: dos CTAs identicos para la misma accion
"Crear una cuenta" y "Salir del modo invitado" ambos llaman exitGuestMode(). Genera confusion: el usuario no sabe si estas son dos acciones diferentes o la misma. Deberian consolidarse en un solo CTA con mejor copy.
ConfiguracionScreen.tsx L242-248: NavRow + Link ambos con onPress={exitGuestMode}
P-M03 · Secciones sin jerarquia visual — todo el mismo peso
6 secciones con el mismo SectionTitle h2, mismo spacing, mismo fondo. Sin iconos en NavRows para scanability. El usuario tiene que leer cada item para encontrar lo que busca.
Bajo
P-L01 · styles en useMemo con dependencia solo en [c] — correcto pero costoso
Los styles se regeneran cada vez que cambia el tema. Dado que el StyleSheet ya es cache-able por React Native, una alternativa mas eficiente seria StyleSheet.create() fuera del componente con colores pasados inline.
P-L02 · Tab "Config" en AppShell no tiene label visible en todos los breakpoints
En pantallas pequenas, el label del tab puede quedar oculto. Verificar que el icono de settings tiene un accessibilityLabel que dice "Configuracion".
Fase 5 · Propuesta de Rediseno
Bloque 1 — Hero de Cuenta
Problema: Identidad derivada del email, sin actividad
Cambio: Avatar grande + username real de la API + stats inline (respuestas/favoritos/descartados) + CTA "Editar perfil"
Beneficio: El usuario se reconoce. Ve su contribucion sin navegar.
Patron UX: Profile hero (Spotify, Twitter, Apple)
Impacto: +confianza +engagement +sentido de pertenencia
Bloque 2 — Datos y Preferencias
Problema: Settings fragmentados entre dos pantallas
Cambio: Ubicacion electoral y cambio de contrasena accesibles desde el hub directamente, sin navegar a PerfilScreen
Beneficio: Un solo lugar para todo lo relacionado con el usuario
Patron UX: Single settings hub (Apple Settings, Android Settings)
Impacto: -friccion -navegacion redundante
Bloque 3 — Zona de Peligro
Problema: Logout visualmente igual a settings normales
Cambio: Zona final con fondo danger-bg, borde danger, "Cerrar sesion" y "Eliminar cuenta" juntos
Beneficio: El usuario entiende el riesgo semanticamente, sin necesidad de leer
Patron UX: Danger zone (Duolingo, GitHub, Notion)
Impacto: -accidentes +claridad +cumplimiento DS-11
Bloque 4 — Modo Invitado Mejorado
Problema: Dos CTAs para la misma accion, copy confuso
Cambio: Un solo CTA con variant="accent" "Crear tu cuenta gratis" + descripcion de beneficios debajo
Beneficio: CTA unico y claro, copy orientado a beneficio
Patron UX: Freemium upgrade prompt (Notion, Spotify)
Impacto: +conversion de guests a usuarios registrados

// Handlers memoizados — no recrear en cada render const handleLogout = useCallback(async () => { try { await logoutApi(); } catch { /* ignorar */ } await logout(); }, [logout]);
const handleReactivarTours = useCallback(async () => { await resetCoachMarks(); toast.info("Tours reactivados", "Volvern a aparecer en cada pantalla clave."); }, [resetCoachMarks, toast]);
const handleCambiarPass = useCallback(async (current: string, next: string) => { try { await cambiar.mutateAsync({ currentPassword: current, newPassword: next }); setPassOpen(false); requestAnimationFrame(() => { toast.success("Contrasena actualizada", "Tu nueva contrasena ya esta activa."); }); } catch (err) { toast.error("No pudimos cambiar la contrasena", getErrorMessage(err)); } }, [cambiar, toast]);
const styles = useMemo(() => StyleSheet.create({ scroll: { backgroundColor: c.bg, flex: 1 }, content: { padding: spacing.sp4, paddingBottom: spacing.sp8, gap: spacing.sp5 }, accountCard: { padding: spacing.sp4, borderRadius: radii.rLg, borderWidth: 1, borderColor: c.border, backgroundColor: c.card, alignItems: "center", gap: spacing.sp2, }, accountName: { ...typography.h3, fontWeight: "700", color: c.text, textAlign: "center" }, accountEmail: { ...typography.small, color: c.textSecondary, textAlign: "center" }, accountCta: { marginTop: spacing.sp2, alignSelf: "stretch" }, statsRow: { flexDirection: "row", gap: spacing.sp2, alignSelf: "stretch" }, statBadge: { flex: 1, padding: spacing.sp2, borderRadius: radii.rMd, borderWidth: 1, borderColor: c.border2, backgroundColor: c.surface, alignItems: "center", }, statValue: { ...typography.h3, fontWeight: "800", color: c.primary }, statLabel: { ...typography.overline, color: c.textSecondary }, section: { gap: spacing.sp2 }, // Danger zone: DS-11 P8 dangerZone: { borderRadius: radii.rLg, borderWidth: 1.5, borderColor: c.danger, backgroundColor: c.dangerBg ?? c.danger + "18", overflow: "hidden", }, dangerHead: { padding: spacing.sp2, paddingHorizontal: spacing.sp3, borderBottomWidth: 1, borderBottomColor: c.danger, }, dangerHeadText: { ...typography.overline, fontWeight: "800", color: c.danger, }, // Guest promo guestCard: { padding: spacing.sp4, borderRadius: radii.rLg, alignItems: "center", gap: spacing.sp3, backgroundColor: c.successBg ?? c.success + "18", borderWidth: 1.5, borderColor: c.success, }, guestTitle: { ...typography.lead, fontWeight: "700", color: c.text, textAlign: "center" }, guestSub: { ...typography.small, color: c.textSecondary, textAlign: "center" }, guestCta: { alignSelf: "stretch" }, }), [c]);
return ( <AppShell active="config" navigation={navigation}> <ScrollView style={styles.scroll} contentContainerStyle={styles.content}> <HomeTopBar brand="Configuracion" />
{/* ── HERO DE CUENTA ── */} {!isGuest && ( <View style={styles.section}> <SectionTitle title="Cuenta" /> <View style={styles.accountCard}> <Avatar initials={initials} size="lg" /> <Text style={styles.accountName} numberOfLines={1}> {username} </Text> {email && ( <Text style={styles.accountEmail} numberOfLines={1}> {email} </Text> )} {/* Estadisticas de actividad (disponibles via perfilQ.data) */} {perfil?.contadores && ( <View style={styles.statsRow}> <StatItem label="Resp." value={perfil.contadores.respuestas} styles={styles} /> <StatItem label="Favs" value={perfil.contadores.favoritos} styles={styles} /> <StatItem label="Desc." value={perfil.contadores.descartados} styles={styles} /> </View> )} <View style={styles.accountCta}> <Button variant="secondary" onPress={() => navigation.navigate("Perfil")}> Editar perfil </Button> </View> </View> </View> )}
{/* ── MIS DATOS ── */} {!isGuest && ( <View style={styles.section}> <SectionTitle title="Mis datos" /> <NavRow label="Mis guardados" subtitle="Favoritos, descartados y posturas guardadas" onPress={() => navigation.navigate("MisGuardados")} /> <NavRow label="Mis respuestas" subtitle="Ver, editar o reiniciar tus respuestas" onPress={() => navigation.navigate("MisRespuestas")} /> <NavRow label="Cambiar mi contrasena" onPress={() => setPassOpen(true)} /> </View> )}
{/* ── ELECCIONES ── */} <View style={styles.section}> <SectionTitle title="Elecciones" /> <NavRow label="Gestion de elecciones" subtitle="Activa o desactiva las elecciones que sigues" onPress={() => navigation.navigate("GestionElecciones")} /> </View>
{/* ── APARIENCIA ── */} <View style={styles.section}> <SectionTitle title="Apariencia" /> <ThemeToggle /> </View>
{/* ── AYUDA ── */} <View style={styles.section}> <SectionTitle title="Ayuda" /> <NavRow label="Ver tours de nuevo" subtitle="Reactiva los coach marks de cada pantalla" onPress={handleReactivarTours} /> </View>
{/* ── MODO INVITADO ── */} {isGuest && ( <View style={styles.guestCard}> <Avatar initials="?" size="md" /> <Text style={styles.guestTitle}>Estas en modo invitado</Text> <Text style={styles.guestSub}> Crea tu cuenta para guardar favoritos y resultados entre dispositivos. </Text> <View style={styles.guestCta}> <Button variant="accent" onPress={exitGuestMode}> Crear cuenta gratis </Button> </View> </View> )}
{/* ── DEBUG (solo dev) ── */} {__DEV__ && ( /* ... igual que antes ... */ )}
{/* ── ZONA DE PELIGRO ── DS-11 P8 */} {!isGuest && ( <View style={styles.dangerZone}> <View style={styles.dangerHead}> <Text style={styles.dangerHeadText}>Zona de peligro</Text> </View> <NavRow label="Cerrar sesion" variant="danger" onPress={handleLogout} /> </View> )}
{/* Salir del modo invitado — solo un CTA, al fondo */} {isGuest && ( <Link block onPress={exitGuestMode} color={c.danger}> Salir del modo invitado </Link> )} </ScrollView>
<CambiarPasswordModal visible={passOpen} onCancel={() => setPassOpen(false)} onSubmit={handleCambiarPass} loading={cambiar.isPending} /> </AppShell> ); }
// Sub-componente local — solo se usa en este screen function StatItem({ label, value, styles }: { label: string; value: number; styles: any }) { return ( <View style={styles.statBadge}> <Text style={styles.statValue}>{value}</Text> <Text style={styles.statLabel}>{label}</Text> </View> ); }
Fase 11 · Justificacion UX / UI
Username real en lugar de email.split
Problema: identidad no reconocible
Beneficio: el usuario se ve reflejado
Patron UX: Identity clarity (Nielsen #1)
Friccion eliminada: "¿Quien soy en esta app?"
Metrica: +confianza percibida, -abandono por confusión
Stats en el hero
Problema: sin feedback de actividad
Beneficio: el usuario ve su contribucion sin navegar
Patron UX: Progress visibility (Spotify, Strava)
Friccion eliminada: navegar a PerfilScreen para ver contadores
Metrica: +engagement +sentido de pertenencia
Cambiar contrasena en el hub
Problema: requeria 2 pantallas para llegar
Beneficio: accesible en 1 tap
Patron UX: Reduce navigation depth (Fitts Law)
Friccion eliminada: Configuracion → Perfil → Cambiar
Metrica: -tiempo de tarea, -navegacion redundante
Zona de peligro visual
Problema: logout visualmente igual a settings
Beneficio: el usuario entiende el riesgo sin leer
Patron UX: Danger Zone (DS-11 P8, Duolingo, GitHub)
Friccion eliminada: ambiguedad semantica del boton secondary azul
Metrica: -accidentes, +clarity
CTA invitado consolidado
Problema: dos CTAs para la misma accion
Beneficio: un solo mensaje claro con copy orientado a beneficio
Patron UX: Freemium upgrade (Notion, Spotify)
Friccion eliminada: confusion entre "Crear cuenta" y "Salir del modo invitado"
Metrica: +conversion de guests
handleLogout y handleReactivarTours con useCallback
Problema: funciones recreadas en cada render
Beneficio: referencias estables para los NavRow receptores
Patron: React optimization (TASK backlog abierto)
Friccion eliminada: re-renders innecesarios
Metrica: +performance percibida en bajo-end devices
