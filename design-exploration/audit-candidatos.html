Critical C-04 MatchTier usa 3 tiers con thresholds incorrectos y azul (info) para tier medio

Tercera instancia del problema de tiers. MatchTier.tsx define su propia funcion tierFromPercent() completamente desconectada de getMatchTier() del service. High A-08 openDetalle stale en useCallback + eslint-disable que oculta el problema

openDetalle cierra sobre matchByCandidato y navigation. No esta en useCallback y no aparece en las dependencias de renderItem. Cuando navigation cambia (re-mount del container de navegacion), los items ya renderizados usan la version vieja del handler. El eslint-disable suprime el warning de React Hooks en lugar de resolver el problema real.

Dependencias de renderItem -- estado actual
matchByCandidato
✓
en deps
openDetalle
✖
NO en deps -- stale closure
navigation
✖
NO en deps (via openDetalle)
// CandidatosScreen.tsx -- antes: openDetalle sin memoizar
const openDetalle = (cand: Candidato) => {
  const matchPct = matchByCandidato.get(cand.id) ?? null;
  navigation.navigate("DetalleCandidato", { ... });
}; // se recrea en cada render

const renderItem = useCallback(
  ({ item: cand }) => (<CandidateCard ... onPress={() => openDetalle(cand)} />),
  // eslint-disable-next-line react-hooks/exhaustive-deps
  [matchByCandidato], // openDetalle ausente, lint suprimido
);

// Despues: openDetalle memoizado, deps completas, sin eslint-disable
const openDetalle = useCallback((cand: Candidato) => {
  const matchPct = matchByCandidato.get(cand.id) ?? null;
  navigation.navigate("DetalleCandidato", {
    candidatoId: cand.id, breakdown: null, matchPct, confianza: null,
  });
}, [matchByCandidato, navigation]);

const renderItem = useCallback(
  ({ item: cand }: { item: Candidato }) => (
    <CandidateCard ... onPress={() => openDetalle(cand)} />
  ),
  [matchByCandidato, openDetalle], // deps completas, sin suprimir
);

/**
* Normaliza un string para busqueda: minusculas + sin acentos.
* "Ramirez" -> "ramirez" | "Bogota" -> "bogota"
*/
export function normalizeForSearch(s: string): string {
  return s.toLowerCase().normalize("NFD").replace(/[\u0300-\u036f]/g, "");
}

Med M-21 filtrosActivosCount calculado dos veces sin useMemo

El conteo de filtros activos se calcula directamente en el cuerpo del componente y luego las mismas variables se usan como deps de chipsActivos. Un useMemo centraliza la derivacion y garantiza coherencia.

const filtrosActivosCount =
  (query.trim() ? 1 : 0) + partidosSel.size + ...
const hayFiltroActivo = filtrosActivosCount > 0;
const filtrosActivosCount = useMemo(
  () => (query.trim() ? 1 : 0) + partidosSel.size
      + (tipoEleccionSel !== null ? 1 : 0)
      + (regionSel !== null ? 1 : 0),
  [query, partidosSel, tipoEleccionSel, regionSel],
);
const hayFiltroActivo = filtrosActivosCount > 0;
Bajos
Low L-07 FlatList sin getItemLayout -- scrollToIndex imposible

Sin getItemLayout, React Native no puede calcular posiciones sin renderizar los elementos. Si en el futuro se necesita scrollToIndex (deep link, notificacion, busqueda con auto-scroll a candidato), fallara en silencio. Si la altura de los cards es fija, el fix es trivial.

// Solo si CandidateCard tiene altura fija conocida
const CARD_HEIGHT = 80; // padding(16*2) + content(48) = 80px
const SEPARATOR_HEIGHT = spacing.sp3; // itemSeparator
// En FlatList:
getItemLayout={(_, index) => ({
  length: CARD_HEIGHT,
  offset: (CARD_HEIGHT + SEPARATOR_HEIGHT) * index,
  index,
})}
